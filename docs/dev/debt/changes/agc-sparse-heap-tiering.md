# libSceAgcDriver

## add Opt-in draw paths

- [Tiered heaps](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (`APS5_TIERED_HEAPS`, or `ANYPS5_GRAPHICS_PRESET` low or medium) - opt-in; tried on NVIDIA's Windows driver only. A releasable heap of at least `APS5_TIERED_HEAP_MIN_MIB` (512) that an address-based build cannot import whole is split into 64 MiB windows instead of `budgetedImportPieces`' prefix import. A window is placed when its pages first hold a non-zero block: in the heap mirror while the mirror windows fit `APS5_TIERED_HEAP_VRAM_MIB` (default: the device-local budget less an eighth and other usage), else in host imports of its committed pages. Placement counts whole windows and is first come, not by GPU use. Pages whose import the budget refuses after evicting idle imports stay in the mirror. A descriptor-bound buffer crossing a window edge is copied per build. Joined heaps are not tiered. The window size, 512 MiB and the eighth are not measured.
- [Tiered heap window moves](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (`APS5_TIERED_HEAP_MOVES`, or `ANYPS5_GRAPHICS_PRESET` low or medium) - opt-in. Hotness is whether the GPU read a window through the BDA table or the CPU wrote it since the last decision, not how much: a window read once counts as much as one read every draw, reads through a bound buffer are not seen, and windows past the 4096 read slots are judged by CPU writes alone. Every `APS5_TIERED_HEAP_MOVE_FRAMES` (8) frames one window moves: the coldest VRAM window to imports while device-local usage is past its budget less an eighth and imports have room, or a recently used imported window back while two windows of VRAM are free; a moved window waits 16 decisions. The move counts and thresholds are not measured.
- [Tiered heap window release](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) - a demoted window's mirror blocks are released only once no region maps them, so a cached shader resource holding one keeps the VRAM. Tiered imports stay within the host heap's reported budget less a sixteenth even with `APS5_HOST_IMPORT_MIB` set; other imports and host-placed allocations do not, and with both heaps past their budgets NVIDIA's Windows driver lost the device.
- [Texture quality](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Texture.cpp) (`ANYPS5_TEXTURE_QUALITY`, or `ANYPS5_GRAPHICS_PRESET`) - opt-in, `medium` or `low`. The top one or two mip levels of a sampled 2D texture are left out of memory, so a guest read of a left-out level gets data the console would not return: a sample reads the first level kept, a texel load (`image_load_mip` through the image table) at a left-out level returns 0, and an unnormalized sample of a reduced texture throws. Textures are reduced only where the device has sparse 2D image residency and `VK_EXT_image_view_min_lod`; elsewhere every level is kept. Render targets and storage images are never reduced.
- [Graphics presets](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Texture.cpp) (`ANYPS5_GRAPHICS_PRESET`) - opt-in. A preset only sets defaults for the memory settings above and the reported output resolution; it does not change the resolution a title renders at, which AnyPS5 cannot change without knowing how the title sizes its targets, and a title that ignores the reported output mode renders as before. `auto` picks from the largest device-local heap (low up to 7 GiB, medium up to 11 GiB), thresholds that are not measured, and does not set the output resolution, which VideoOut reads before the driver knows the device.
