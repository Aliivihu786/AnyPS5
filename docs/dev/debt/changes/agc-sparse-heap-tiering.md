# libSceAgcDriver

## add Opt-in draw paths

- [Tiered heaps](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (`APS5_TIERED_HEAPS`) - opt-in; tried on NVIDIA's Windows driver only. A releasable heap of at least `APS5_TIERED_HEAP_MIN_MIB` (512) that an address-based build cannot import whole is split into 64 MiB windows instead of `budgetedImportPieces`' prefix import. A window is placed when its pages first hold a non-zero block: in the heap mirror while the mirror windows fit `APS5_TIERED_HEAP_VRAM_MIB` (default: the device-local budget less an eighth and other usage), else in host imports of its committed pages. Placement counts whole windows and is first come, not by GPU use. Pages whose import the budget refuses after evicting idle imports stay in the mirror. A descriptor-bound buffer crossing a window edge is copied per build. Joined heaps are not tiered. The window size, 512 MiB and the eighth are not measured.
- [Tiered heap window moves](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (`APS5_TIERED_HEAP_MOVES`) - opt-in. Hotness is CPU write stamps, not GPU reads: a window the GPU reads every frame but the CPU never writes is cold. Every `APS5_TIERED_HEAP_MOVE_FRAMES` (8) frames one window moves: the coldest VRAM window to imports while device-local usage is past its budget less an eighth and imports have room, or an imported window written in the last 8 decisions back while two windows of VRAM are free; a moved window waits 16 decisions. A demoted window's mirror blocks are released only once no region maps them, so a cached shader resource holding one keeps the VRAM. Tiered imports stay within the host heap's reported budget less a sixteenth even with `APS5_HOST_IMPORT_MIB` set; other imports and host-placed allocations do not, and with both heaps past their budgets NVIDIA's Windows driver lost the device. The move counts and thresholds are not measured.
- [Texture quality](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Texture.cpp) (`ANYPS5_TEXTURE_QUALITY`) - opt-in, `medium` or `low`. The top one or two mip levels of a sampled 2D texture are left out of memory, so a guest read of a left-out level gets data the console would not return: a sample reads the first level kept, a texel load (`image_load_mip` through the image table) at a left-out level returns 0, and an unnormalized sample of a reduced texture throws. Textures are reduced only where the device has sparse 2D image residency and `VK_EXT_image_view_min_lod`; elsewhere every level is kept. Render targets and storage images are never reduced.
